# NFe Agendamento 2.0 v0.0.4 Reliability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Corrigir os problemas de confiabilidade da distribuição `v0.0.3` sem alterar lógica fiscal, parser XML, Fernando Klein ou DANFE, e publicar uma `v0.0.4` validada no mesmo SHA do CI.

**Architecture:** A origem oficial passa a morar na configuração de produção do Bridge, não no wizard do instalador. O Bridge ganha uma trava de instância única antes de subir o host; o cliente web passa a usar timeouts por operação; e a disponibilidade do Portal passa a depender de um probe headless do próprio helper WebView2. O Setup continua simples, por usuário, self-contained e sem UAC.

**Tech Stack:** .NET 10 / ASP.NET Core, C# xUnit, Vite + TypeScript + Vitest, WinForms + Microsoft WebView2, Inno Setup, GitHub Actions, Wrangler/Cloudflare.

**Spec:** `docs/superpowers/specs/2026-09-08-v0.0.4-reliability-design.md`

## Global Constraints

- Origem oficial de produção: `https://nfeagendamento.joaolds.xyz.br`.
- Bridge somente em `http://127.0.0.1:17345`.
- Nunca usar wildcard de Origin/CORS.
- Setup por usuário em `%LOCALAPPDATA%\NFe Agendamento Bridge`, `PrivilegesRequired=lowest`.
- Bridge e Portal publicados `win-x64 --self-contained true`.
- Nenhum serviço Windows, tarefa agendada, regra de firewall ou updater.
- Não alterar protocolo fiscal, tratamento Fernando Klein, parser XML ou DANFE.
- Sem retry fiscal automático em falhas ambíguas.
- `v0.0.3` permanece imutável; a correção sai como `v0.0.4`.

- [ ] **Step 3: Implementar `BridgeSingleInstance`**

Criar `Runtime/BridgeSingleInstance.cs`:

```csharp
namespace NfeAgendamento.Bridge.Runtime;

public sealed class BridgeSingleInstance : IDisposable
{
    private readonly Mutex _mutex;
    private bool _disposed;

    private BridgeSingleInstance(Mutex mutex) => _mutex = mutex;

    public static bool TryAcquire(string name, out BridgeSingleInstance? instance)
    {
        if (string.IsNullOrWhiteSpace(name))
            throw new ArgumentException("Nome da instância inválido.", nameof(name));

        var mutex = new Mutex(initiallyOwned: true, name, out var createdNew);
        if (!createdNew)
        {
            mutex.Dispose();
            instance = null;
            return false;
        }

        instance = new BridgeSingleInstance(mutex);
        return true;
    }

    public void Dispose()
    {
        if (_disposed) return;
        _disposed = true;
        try { _mutex.ReleaseMutex(); }
        catch (ApplicationException) { }
        _mutex.Dispose();
    }
}
```

private async request(
  path: string,
  init: RequestInit,
  timeoutMs: number,
  signal?: AbortSignal,
): Promise<Response> {
  const timeoutController = new AbortController();
  const timeout = globalThis.setTimeout(() => timeoutController.abort(), timeoutMs);
  const requestSignal = signal ? AbortSignal.any([signal, timeoutController.signal]) : timeoutController.signal;

  try {
    const response = await fetch(`${this.baseUrl}${path}`, {
      ...init,
      cache: 'no-store',
      headers: { Accept: 'application/json', ...init.headers },
      signal: requestSignal,
    });
    if (!response.ok) throw new Error(`Bridge indisponível (${response.status})`);
    return response;
  } finally {
    globalThis.clearTimeout(timeout);
  }
}

- [ ] **Step 4: Implementar probe headless no launcher**

Em `ProcessPortalWindowLauncher.cs`:

```csharp
private readonly Func<string, bool> _runtimeProbe;

public bool IsAvailable =>
    OperatingSystem.IsWindows() &&
    File.Exists(_helperPath) &&
    _runtimeProbe(_helperPath);

private static bool ProbeRuntime(string helperPath)
{
    try
    {
        using var process = Process.Start(new ProcessStartInfo
        {
            FileName = helperPath,
            UseShellExecute = false,
            CreateNoWindow = true,
            WorkingDirectory = Path.GetDirectoryName(helperPath) ?? AppContext.BaseDirectory,
            ArgumentList = { "--probe-runtime" },
        });

        if (process is null) return false;
        if (!process.WaitForExit(milliseconds: 1_500))
        {
            try { process.Kill(entireProcessTree: true); } catch (InvalidOperationException) { }
            return false;
        }

        return process.ExitCode == 0;
    }
    catch (Exception exception) when (
        exception is IOException or UnauthorizedAccessException or InvalidOperationException or System.ComponentModel.Win32Exception)
    {
        return false;
    }
}
```

Se a coleção `ArgumentList` não aceitar initializer nessa forma no compilador, criar `ProcessStartInfo`, depois `startInfo.ArgumentList.Add("--probe-runtime")` antes de `Process.Start(startInfo)`.
