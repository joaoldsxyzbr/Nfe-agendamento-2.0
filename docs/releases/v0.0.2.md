# NFe Agendamento 2.0 — v0.0.2

Release focada na instalação do **NFe Agendamento Bridge** no Windows.

## Principal mudança

O Bridge deixa de depender do ZIP portátil como experiência principal. A release inclui um instalador `Setup.exe` por usuário, simples e sem necessidade de administrador.

## Instalador Windows

- download principal: `NFeAgendamentoBridge-Setup-v0.0.2.exe`;
- instala em `%LOCALAPPDATA%\NFe Agendamento Bridge`;
- não solicita elevação/UAC de administrador;
- instala `NfeAgendamento.Bridge.exe` e `NfeAgendamento.Portal.exe` lado a lado;
- cria atalho no Menu Iniciar;
- registra o Bridge para iniciar automaticamente no login do usuário atual;
- inicia o Bridge ao concluir a instalação quando a opção permanecer marcada;
- usa ícone próprio azul-escuro e amarelo no Bridge, atalho e instalador;
- desinstalação remove arquivos instalados, atalho e auto-start;
- a configuração local em `%LOCALAPPDATA%\NfeAgendamentoBridge` não é apagada automaticamente, permitindo preservar a seleção do certificado em uma reinstalação;
- não existe updater automático, serviço Windows, tarefa agendada ou alteração de firewall.

## Fallback técnico

`NfeAgendamentoBridge-win-x64.zip` continua disponível para diagnóstico/uso técnico. Para uso normal, prefira o instalador.

## Requisitos no Windows

- Windows 10/11 x64;
- .NET 10 Desktop Runtime;
- Microsoft Edge WebView2 Runtime;
- certificado A1 válido instalado em `CurrentUser/My`;
- origem HTTPS exata do site configurada em `Bridge:AllowedOrigins` antes do uso em produção.

O Bridge continua restrito a `127.0.0.1:17345`; esta release não altera CORS, Host, protocolo fiscal ou segurança de loopback.

## Atualizações futuras

Não há atualização automática. Se algum dia o Bridge precisar mudar por alteração da SEFAZ, Portal, WebView2/.NET ou correção técnica, uma nova versão poderá ser instalada por cima.

## Validação

O `Setup.exe` é compilado pelo Inno Setup no runner Windows do GitHub Actions e a release só é publicada depois que web, Bridge, helper WebView2 e empacotamento Windows passam no mesmo CI.

A validação física com Windows real, certificado A1, SEFAZ e fallback Portal/hCaptcha continua sendo necessária antes de declarar o ambiente de produção validado.
