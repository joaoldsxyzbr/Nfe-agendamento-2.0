# NFe Agendamento 2.0 — v0.0.19

Release B da migração site-first. Esta versão muda somente o lifecycle/UX do componente Windows e preserva as fronteiras fiscais entregues na v0.0.18.

## Principais mudanças

- `NfeAgendamento.App.exe` passa a funcionar como supervisor headless de transição, sem bandeja visível, menu, duplo clique, abertura automática do site ou UI própria de atualização;
- o site permanece como única interface normal para consulta, diagnóstico e descoberta de atualização;
- `BridgeControlClient`, lease, heartbeat, backoff/restart e shutdown controlado continuam ativos no modo padrão `app`;
- o instalador ganha `BridgeAutostartMode=app|standalone`, mantendo `app` como padrão;
- o modo `standalone` inicia diretamente `NfeAgendamento.Bridge.exe`, sem `--managed`, e continua mantendo o App dentro do pacote para rollback;
- o CI compila também o Setup em modo standalone como gate técnico, em diretório isolado e sem publicar esse piloto como asset oficial;
- documentação de segurança, atualização, frontend e aceitação foi alinhada ao lifecycle de transição.

## O que não mudou

- transporte fiscal `NFeDistribuicaoDFe`;
- `FiscalUsageGuard` e coordenação multi-PC;
- ausência de retry fiscal automático;
- Bridge restrito a `127.0.0.1:17345`;
- validação de Origin/Host;
- certificado A1 e chave privada permanecendo somente no Windows;
- helper Portal/WebView2 e hCaptcha manual;
- persistência em `%LOCALAPPDATA%\NfeAgendamentoBridge`;
- App, Bridge e Portal continuam empacotados nesta release.

## Upgrade da v0.0.18

O Setup oficial v0.0.19 continua usando o modo padrão `app`. Ele pode ser instalado sobre a v0.0.18 e deve preservar:

- `settings.json`;
- `fiscal-usage.json`;
- `supplier-rules.json`;
- dados locais necessários ao perfil do helper Portal.

Depois do upgrade, o App não exibe mais ícone/menu; o diagnóstico e a atualização passam pelo site.

## Piloto standalone

O modo standalone é opt-in de build e não substitui o Setup oficial padrão desta release.

Para testar, compile o instalador com `BridgeAutostartMode=standalone` e siga `docs/testing/standalone-bridge.md`.

Se o piloto standalone apresentar problema, o rollback correto é reinstalar o Setup oficial v0.0.19 no modo padrão `app`. Não execute o App diretamente enquanto um Bridge standalone estiver ativo, porque o supervisor controla somente instâncias iniciadas com `--managed`.

Se for necessário reverter a Release B inteira, reinstale o Setup oficial v0.0.18.

## Validação automatizada

A publicação desta release fica condicionada ao mesmo commit concluir com sucesso:

- `web`;
- `danfe-print`;
- `bridge`;
- `fiscal-compatibility`;
- `windows-package`;
- compilação não publicada do instalador standalone;
- CodeQL para JavaScript/TypeScript e C#.

## Gate para a próxima etapa

A v0.0.19 **não remove o App**.

A Task 8 só pode aposentar o supervisor depois de uma release de transição estável e de evidência suficiente para os gates documentados: startup/logon, instância única, persistência, Portal, update/rollback e ausência de falhas que justifiquem manter o supervisor.

Sem essa evidência, o App permanece headless.
