# NFe Agendamento 2.0 — v0.0.23

Release de correção do piloto **site + extensão**, ainda preservando o Bridge no fluxo normal.

## Correção principal

A extensão Chromium passa para **v0.2.1** e corrige falsos estados **Extensão não conectada** causados por corrida entre o carregamento da página, a injeção do content script e o cold start do service worker.

Mudanças:

- o handshake do site tenta novamente quando a ponte ainda não respondeu;
- a extensão reinjeta `site-bridge.js` de forma segura em abas oficiais já abertas durante instalação/inicialização;
- a ponte passou a ser idempotente para evitar listeners duplicados;
- a página `/extension-test.html` revalida a extensão quando a aba volta ao foco;
- nenhuma permissão nova foi adicionada.

## Arquitetura

Esta release não remove o Bridge, WebView2, consulta direta SEFAZ, proteção fiscal ou coordenação multi-PC. O gate sem Bridge continua sendo um piloto físico separado.

O fluxo do gate permanece:

```text
site
  → extensão Chromium
    → popup do Portal Nacional
      → hCaptcha manual
      → certificado A1 pelo navegador/Windows
      → XML oficial
        → site / DANFE
```

## Teste extension-only

1. remova/desabilite versões antigas da extensão;
2. extraia `NFeAgendamento-Extension-v0.2.1.zip`;
3. em `chrome://extensions` ou `edge://extensions`, habilite o modo de desenvolvedor e use **Carregar sem compactação**;
4. abra ou volte para `https://nfeagendamento.joaolds.xyz.br/extension-test.html`;
5. confirme **Extensão conectada · versão 0.2.1**;
6. somente depois execute uma consulta real com NF-e legítima;
7. resolva o hCaptcha manualmente e use o A1 quando o navegador solicitar.

Se o navegador ou uma política corporativa bloquear extensões descompactadas, o código não tenta contornar a política. Nesse caso a instalação precisa ser permitida pelo ambiente ou migrada para distribuição por loja/política gerenciada.

## Segurança

Continuam válidas as fronteiras do piloto:

- Manifest V3;
- `scripting`, `storage` e `webRequest`;
- hosts limitados ao domínio oficial e ao Portal Nacional;
- sem `<all_urls>`;
- sem Native Messaging;
- sem solver de captcha;
- sem PFX/P12/chave privada no código;
- sem ampliação de acesso ao sistema de arquivos.

## Validação

O CI deve validar web, extensão, DANFE/Playwright, Bridge, compatibilidade fiscal e pacote Windows no mesmo SHA antes da publicação automática da release.

A validação física **Chrome/Edge + A1 + Portal + hCaptcha + XML sem Bridge** continua obrigatória antes da remoção do Bridge.
