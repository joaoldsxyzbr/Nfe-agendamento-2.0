# NFe Agendamento 2.0 — v0.0.7

Release de teste com foco em simplificar o fallback pelo Portal Nacional da NF-e e reduzir a interação manual após o hCaptcha, preservando as proteções fiscais e de segurança já existentes.

## Principais mudanças

- mantém a consulta direta via SEFAZ como caminho padrão;
- Portal Nacional continua sendo acionado somente após `consumption_limit` / limite de consumo;
- chave NF-e continua sendo preenchida automaticamente no Portal;
- **hCaptcha permanece manual**: o usuário continua sendo responsável por resolver o desafio;
- depois que o próprio hCaptcha publica uma resposta válida, o helper aciona automaticamente a consulta oficial;
- quando o Portal disponibiliza **Download do Documento**, o helper aciona o download automaticamente;
- `Alert`/`Confirm` do Portal só pode ser aceito automaticamente durante o clique controlado do download reconhecido;
- certificado A1 continua sendo selecionado pelo thumbprint previamente escolhido;
- somente o endpoint oficial `/portal/downloadNFe.aspx` é aceito para o XML;
- XML continua limitado a 10 MiB e validado contra a chave antes de retornar ao site;
- não existe `hcaptcha.execute`, `grecaptcha.execute`, serviço de resolução, fabricação de token ou bypass de captcha;
- helper Portal continua persistente e reutilizado entre operações sequenciais;
- interface de consulta foi simplificada com resultado integrado e ação **Nova consulta**;
- topo do site ganhou atalho para baixar o app Windows;
- o atalho de download agora aponta para o Setup `v0.0.7` desta própria release.

## Segurança preservada

- Bridge restrito a `127.0.0.1:17345`;
- origem oficial fixa em `https://nfeagendamento.joaolds.xyz.br`;
- chave privada do A1 permanece somente no Windows local;
- navegação do WebView2 permanece limitada ao host oficial `www.nfe.fazenda.gov.br`;
- popups e navegação externa continuam bloqueados;
- nenhuma repetição fiscal automática foi adicionada;
- uma única operação Portal por PC continua sendo permitida;
- validação XML defensiva permanece com DTD proibido e `XmlResolver = null`.

## Instalação / atualização

Asset principal:

```text
NFeAgendamentoBridge-Setup-v0.0.7.exe
```

Quem já estiver na `v0.0.6` pode usar **Verificar atualizações** no app da bandeja. O atualizador continua exigindo confirmação explícita e valida nome/URL, tamanho publicado e SHA-256 antes de executar o Setup.

A instalação permanece por usuário em `%LOCALAPPDATA%\NFe Agendamento Bridge`, sem exigir UAC/admin, com App + Bridge + helper Portal self-contained para `win-x64`.

## Validação

A release só deve ser publicada a partir dos artifacts produzidos pelo CI verde do mesmo commit marcador:

```text
release: v0.0.7
```

O CI valida web, suíte .NET, build/publish do Bridge, publish do `NfeAgendamento.Portal.exe` no Windows, tray app, instalador e pacote técnico.

Ainda é obrigatório teste físico em Windows real para o fluxo externo do Portal Nacional. Em uma ocorrência natural/controlada de limite, o comportamento nominal esperado é: **abrir Portal → usuário resolve hCaptcha → restante do fluxo segue automaticamente → XML retorna ao site**.

Não provoque `656` repetindo consultas artificialmente apenas para testar o fallback.

Detalhes do fluxo e checklist específico: `docs/testing/portal-post-hcaptcha.md`.
