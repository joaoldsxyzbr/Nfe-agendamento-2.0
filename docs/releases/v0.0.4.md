# NFe Agendamento 2.0 — v0.0.4

Release corretiva de confiabilidade do **NFe Agendamento Bridge** e da distribuição Windows.

## Correções

- origem de produção fixa em `https://nfeagendamento.joaolds.xyz.br`;
- removida a tela do instalador que solicitava a URL do site;
- Bridge passa a aceitar somente a origem oficial em produção, sem wildcard;
- proteção de instância única para evitar dois Bridges disputando `127.0.0.1:17345`;
- timeouts do site separados por operação: health curto, operações locais curtas, consulta NF-e com margem sobre o timeout SEFAZ e Portal independente;
- `webView2Available` agora exige helper presente e probe real do Microsoft Edge WebView2 Runtime;
- o probe do WebView2 é headless e não abre a janela do Portal durante `/health`;
- Bridge e Portal helper continuam self-contained `win-x64`, sem exigir instalação externa do .NET 10.

## Instalação

Use:

```text
NFeAgendamentoBridge-Setup-v0.0.4.exe
```

O fluxo de instalação volta a ser simples:

```text
Avançar → Instalar → Concluir
```

O usuário não informa mais domínio/origem. A origem oficial já faz parte da configuração distribuída.

O Setup continua:

- instalando somente para o usuário atual em `%LOCALAPPDATA%\NFe Agendamento Bridge`;
- sem solicitar administrador/UAC;
- criando atalho no Menu Iniciar;
- registrando auto-start no usuário atual;
- preservando `%LOCALAPPDATA%\NfeAgendamentoBridge` com a seleção local do certificado;
- sem serviço Windows, tarefa agendada, alteração de firewall ou updater automático.

## Segurança preservada

- Bridge somente em `127.0.0.1:17345`;
- Host estrito;
- CORS/origin allowlist sem wildcard;
- chave privada A1 permanece no Windows;
- helper Portal restrito ao Portal Nacional;
- hCaptcha sempre manual;
- downloads externos bloqueados;
- nenhum retry fiscal automático após falhas ambíguas.

## Escopo fiscal

Esta release **não altera** protocolo fiscal, parser XML, tratamento Fernando Klein nem layout/DANFE. As mudanças são somente de confiabilidade da integração local e distribuição Windows.

## Validação automatizada

O CI executa:

- testes web;
- build web;
- `wrangler deploy --dry-run`;
- testes Bridge;
- build Bridge;
- build Portal helper;
- publish self-contained `win-x64` dos dois executáveis;
- compilação real do Inno Setup em runner Windows;
- geração dos artifacts `NFeAgendamentoBridge-Setup-v0.0.4` e `NfeAgendamentoBridge-win-x64`.

A release só é publicada a partir dos artifacts do mesmo CI verde do commit marcador `release: v0.0.4`.

## Aceitação física

Ainda deve ser validado em Windows real: instalação, ausência de UAC, auto-start, segunda execução, navegador → loopback, certificado A1 real, consulta SEFAZ, DANFE/PDF e fallback Portal/hCaptcha.
