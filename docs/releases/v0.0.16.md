# NFe Agendamento 2.0 — v0.0.16

Release corretiva do fluxo de atualização/download construída sobre a v0.0.15.

## Correção principal

A v0.0.15 fazia o App e o botão de download do site acessarem diretamente endpoints do GitHub. Em ambientes onde esse caminho responde com timeout/HTTP 504, tanto a atualização interna quanto o download manual podem falhar.

A v0.0.16 remove essa dependência direta do cliente.

## Novo fluxo de atualização

- o App consulta `https://nfeagendamento.joaolds.xyz.br/api/update/latest`;
- o site baixa pelo caminho `/downloads/windows/v0.0.16/NFeAgendamentoBridge-Setup-v0.0.16.exe`;
- o Worker consulta a release oficial no GitHub server-side;
- a metadata devolvida ao App contém apenas a release/asset esperados e uma URL do próprio domínio;
- o Setup é transmitido pelo Worker sem redirecionar o cliente para o GitHub.

## Restrições de segurança

O Worker não é um proxy genérico.

A rota de download aceita somente:

```text
/downloads/windows/vX.Y.Z/NFeAgendamentoBridge-Setup-vX.Y.Z.exe
```

com a mesma versão no tag e no nome. A origem upstream é construída internamente para o repositório oficial. A metadata exige:

- release estável;
- tag `vX.Y.Z`;
- asset com nome exato;
- estado `uploaded`;
- tamanho positivo;
- digest `sha256:<64 hex>`;
- URL original exatamente correspondente ao asset esperado no repositório.

O App continua validando tamanho efetivo e SHA-256 antes de executar qualquer instalador.

## Tratamento de falhas

Timeout, exceção de rede ou resposta não-2xx do GitHub no lado do Worker retorna indisponibilidade controlada (`502 update_source_unavailable`) e nenhum arquivo parcial é aceito pelo updater.

## Migração a partir da v0.0.15

O updater já compilado na v0.0.15 ainda contém o acesso direto ao GitHub e não pode ser alterado retroativamente.

Se **Verificar atualizações** na v0.0.15 continuar falhando, usar uma vez o botão de download do site para obter e instalar a v0.0.16. Depois da v0.0.16, as próximas atualizações usam o domínio oficial.

## Arquitetura preservada

Esta correção não altera:

- consulta SEFAZ;
- proteção fiscal local/multi-PC;
- certificado A1;
- Bridge loopback;
- Portal/hCaptcha;
- DANFE;
- fluxo em lote.

## Validação automatizada

A publicação depende do mesmo SHA concluir com sucesso:

- `web`;
- `danfe-print`;
- `bridge`;
- `fiscal-compatibility`;
- `windows-package`.

O CodeQL continua separado. Os testes novos cobrem metadata, origem do updater, caminho permitido do Setup, rejeição de arquivo arbitrário e erro upstream.

## Validações externas ainda pendentes

Continuam dependentes de ambiente real:

- teste físico de atualização da v0.0.15 para a v0.0.16;
- A4/impressora real;
- certificado A1/SEFAZ/Portal reais;
- Authenticode;
- proteção administrativa da `main`.

O commit marcador desta release deve usar exatamente:

```text
release: v0.0.16
```
