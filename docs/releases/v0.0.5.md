# NFe Agendamento 2.0 — v0.0.5

Release corretiva da experiência Windows do **NFe Agendamento Bridge**.

## Correção principal

A versão anterior iniciava diretamente `NfeAgendamento.Bridge.exe`, expondo a janela de console do ASP.NET e sem presença na bandeja do Windows.

A `v0.0.5` adiciona um shell Windows próprio, `NfeAgendamento.App.exe`, que:

- inicia o Bridge local sem abrir janela de console;
- permanece na bandeja do Windows com o ícone do NFe Agendamento;
- abre `https://nfeagendamento.joaolds.xyz.br` com duplo clique no ícone;
- oferece no menu da bandeja **Abrir NFe Agendamento** e **Sair**;
- mantém instância única do shell;
- encerra o Bridge local ao escolher **Sair**.

O instalador, atalho do Menu Iniciar e auto-start passam a iniciar `NfeAgendamento.App.exe`. O processo `NfeAgendamento.Bridge.exe` continua existindo apenas como componente local de backend em `127.0.0.1:17345`.

## Instalação

Use:

```text
NFeAgendamentoBridge-Setup-v0.0.5.exe
```

O Setup continua por usuário, sem UAC/admin, em `%LOCALAPPDATA%\NFe Agendamento Bridge`.

## Escopo preservado

Esta release não altera protocolo fiscal, certificado A1, parser XML, tratamento Fernando Klein, DANFE, site nem fallback Portal. A mudança é restrita à inicialização e presença do Bridge no Windows.

## Validação automatizada

O CI valida:

- testes web e Bridge;
- build do Bridge e Portal helper;
- build do novo `NfeAgendamento.App`;
- publish self-contained `win-x64` dos três executáveis;
- compilação real do Inno Setup;
- geração do instalador `NFeAgendamentoBridge-Setup-v0.0.5.exe`;
- testes estáticos que exigem `WinExe`, `NotifyIcon`, execução oculta do Bridge e instalador apontando para o shell de bandeja.

## Aceitação física

No Windows real, confirmar após instalar:

1. nenhuma janela preta de console permanece aberta;
2. o ícone do NFe Agendamento aparece na bandeja;
3. duplo clique no ícone abre o site;
4. **Sair** remove o ícone e encerra o Bridge;
5. após entrar novamente no Windows, o app inicia direto na bandeja.
