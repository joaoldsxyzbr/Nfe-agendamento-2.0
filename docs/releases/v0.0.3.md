# NFe Agendamento 2.0 — v0.0.3

Release corretiva da distribuição Windows do **NFe Agendamento Bridge**.

## Correções principais

- Bridge publicado como **self-contained para Windows x64**: não depende de uma instalação prévia do .NET 10 para iniciar.
- Helper Portal também publicado como self-contained.
- O instalador passa a solicitar a **origem HTTPS exata do site** durante a instalação.
- A origem informada é validada sem wildcard, caminho, query string, fragmento, userinfo, aspas ou espaços.
- A configuração `Bridge:AllowedOrigins:0` é aplicada ao primeiro start, ao atalho do Menu Iniciar e ao auto-start em `HKCU`.
- Mantidas as restrições de segurança: loopback `127.0.0.1:17345`, Host estrito e CORS fail-closed.

## Instalação

Use:

```text
NFeAgendamentoBridge-Setup-v0.0.3.exe
```

O Setup continua:

- instalando somente para o usuário atual em `%LOCALAPPDATA%\NFe Agendamento Bridge`;
- sem solicitar administrador/UAC;
- criando atalho no Menu Iniciar;
- iniciando o Bridge automaticamente no login do usuário atual;
- permitindo desinstalação limpa do executável, atalho e auto-start;
- preservando a configuração local do certificado em uma reinstalação;
- sem updater automático, serviço Windows, tarefa agendada ou alteração de firewall.

Na tela **Site do NFe Agendamento**, informe somente a origem que aparece no navegador, por exemplo:

```text
https://nfe.exemplo.com
```

Não informe caminhos como `/consulta` nem query strings.

## Requisitos

- Windows 10/11 x64;
- Microsoft Edge WebView2 Runtime somente para o fallback pelo Portal Nacional;
- certificado A1 válido instalado em `CurrentUser/My`.

A instalação externa do .NET 10 deixa de ser requisito desta distribuição.

## Migração da v0.0.2

A `v0.0.2` é substituída por esta versão por dois problemas de distribuição: dependência externa do runtime .NET e ausência da origem HTTPS na inicialização de produção. Instale a `v0.0.3` sobre a versão anterior ou desinstale a antiga antes de instalar a nova.

## Validação

O CI executa testes web e Bridge, builds, `wrangler deploy --dry-run`, publish self-contained de Bridge/Portal e compilação real do `Setup.exe` em runner Windows. A release só é publicada quando esses gates passam no mesmo commit.

A confirmação final continua sendo o teste físico em Windows real com certificado A1, SEFAZ e fallback Portal/hCaptcha.
