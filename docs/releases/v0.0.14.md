# NFe Agendamento 2.0 — v0.0.14

Release de hardening fiscal, compatibilidade futura e robustez do DANFE construída sobre a v0.0.13.

## Principais mudanças

- suporte completo a chave NF-e de **44 caracteres** com CNPJ/chave alfanuméricos e DV vigente;
- rejeição explícita de NFC-e modelo 65, mantendo o produto restrito a NF-e modelo 55;
- DANFE revisado com NCM/SH, coluna `Item`, código de barras híbrido CODE-128C/CODE-128A e paginação determinística;
- folhas adicionais do DANFE repetem os cabeçalhos fiscais necessários e preservam a ordem dos itens;
- regressão automatizada de impressão A4 com Playwright/Chromium, cobrindo overflow, paginação, cabeçalhos, NCM/SH e chave alfanumérica;
- regras específicas de fornecedores mantidas sem CPF/CNPJ fixos no bundle público;
- proteção fiscal local reforçada com persistência durável e recuperação fail-safe de estado corrompido;
- nova coordenação **multi-PC** do teto fiscal para computadores que usam cópias do mesmo A1 RSA;
- o coordenador Cloudflare usa Durable Object e recebe somente uma credencial opaca derivada localmente do A1, sem CNPJ, chave NF-e, XML, PFX, senha ou chave privada;
- `429` e `cStat 656` propagam cooldown compartilhado entre os PCs coordenados;
- se a coordenação compartilhada estiver indisponível ou inválida, o Bridge não consulta a SEFAZ e segue de forma conservadora pelo Portal;
- POC isolado de `Unimake.DFe` para paridade de chave alfanumérica e estrutura RTC;
- parser estrutural complementar de IBS/CBS/IS preparado sem alterar prematuramente o DANFE de produção;
- diagnóstico local e documentação revisados para chave alfanumérica;
- link de download do site atualizado para o Setup v0.0.14.

## Arquitetura

A arquitetura continua simples para uso interno:

- site Cloudflare para interface, XML, DANFE e lote;
- App/Bridge local em cada PC;
- certificado A1 e chave privada permanecem no Windows;
- sem Central, pareamento, LAN, mDNS ou pasta compartilhada;
- Worker/Durable Object remoto usado somente para coordenar o consumo fiscal entre PCs.

## Segurança e comportamento fiscal

- Bridge somente em `127.0.0.1:17345`;
- nenhuma repetição fiscal automática após erro ambíguo ou limite;
- fallback Portal mantém hCaptcha manual;
- XML retornado é validado contra a chave consultada;
- logs não persistem chave NF-e, XML, PFX, senha ou chave privada;
- o coordenador remoto não recebe dados fiscais do documento;
- estado local corrompido falha de modo conservador em vez de liberar novas chamadas SEFAZ.

## Validação automatizada

A publicação desta release depende do mesmo SHA concluir com sucesso os jobs:

- `web`;
- `danfe-print`;
- `bridge`;
- `fiscal-compatibility`;
- `windows-package`.

O workflow de release publica somente os artifacts produzidos pelo CI verde daquele mesmo SHA.

## Validação física ainda pendente

A v0.0.14 pode ser publicada e usada internamente, mas só deve ser declarada **fisicamente validada** depois de executar os checklists de ambiente real:

- `docs/testing/acceptance.md`;
- `docs/testing/batch-query.md`;
- `docs/testing/danfe-layout.md`;
- `docs/testing/portal-post-hcaptcha.md`.

O CI não consegue provar comportamento de uma impressora/driver específico, interação real com certificado A1, SEFAZ ou hCaptcha.

Não provoque bloqueio `656` artificialmente apenas para testar o fallback.

## Controles externos ainda pendentes

- Authenticode depende de certificado real de code signing e dos secrets correspondentes;
- proteção administrativa da `main` depende de ruleset/branch protection configurado com permissão administrativa no GitHub.

Esses controles são recomendados, mas não alteram a arquitetura funcional do app para uso interno.

## Atualização

A atualização a partir da v0.0.13 é suportada pelo atualizador manual da bandeja. O Setup continua por usuário, sem necessidade de administrador, e preserva os dados locais de configuração em `%LOCALAPPDATA%\NfeAgendamentoBridge`.

O commit marcador desta release deve usar exatamente:

```text
release: v0.0.14
```
